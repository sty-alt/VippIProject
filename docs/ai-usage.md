# Реально использованные AI-инструменты

Дата: 13 октября 2026.

## Разработка

Codex использовался для анализа задания, проектирования модели данных и транзакций, написания Next.js/TypeScript/Prisma кода, форм, серверных проверок, тестов и документации. Команды выполнялись в локальном терминале. Результаты проверок перечислены в verification.md, а не выводятся из наличия исходников.

Exa использован для поиска официальных страниц RepairDesk, Orderry и Jobber. Официальные документы Next.js, Prisma, Better Auth, Tailwind, Vitest, Playwright и HTTP Chat API прочитаны через web tools. Конкурентное сравнение ограничено подтверждёнными сведениями и не включает выдуманные интервью или продажи.

Применены инструкции brainstorming, frontend-design, Vercel React Best Practices и OpenAI Docs. Дизайн следует предоставленному заданию. Инструкция пользователя об автономной реализации имела приоритет над дополнительными согласованиями. При первоначальной реализации код не отправлялся во внешние системы. Затем пользователь отдельно запросил GitHub-публикацию и комплект сдачи: репозиторий sty-alt/VippIProject получает исходники, снимки с вымышленными данными и итоговые материалы. Секреты, `.env`, база, сессии и локальные файлы входа исключены.

Для комплекта сдачи использован навык Presentations и Artifact Tool: 12 редактируемых слайдов, реальные снимки интерфейса и заметки выступающего. Двухстраничный PDF подготовлен ReportLab. MP4-обзор использует изображения слайдов и офлайн-системный голос Microsoft Irina Desktop, синтезированный установленными средствами Windows. Это не запись непрерывного взаимодействия и не проверка AI-модели продукта. Настоящий ручной сценарий подтверждён отдельным Playwright-тестом. Base44, Notion, Figma, Canva и генераторы иллюстраций/видео для этого комплекта не использовались.

По запросу пользователя MP4 заменён новой записью работы приложения с настоящим AI-запросом. Использованы отдельные браузерные сессии владельца и клиента, нейросетевой русский голос `ru-RU-SvetlanaNeural` через Edge online speech и FFmpeg для монтажа глав и нормализации громкости. Шаблонные ответы провайдера не подставлялись; результат проверен и отредактирован человеком перед публикацией сметы. Голос синтетический. Попытка использовать Runway для озвучки потребовала повторного подключения; выбран доступный нейросетевой голос. Вспомогательные записи, cookies, ключ и локальные файлы входа исключены из Git. PowerPoint/PDF презентации сохранены как материалы первого этапа.

## AI внутри продукта

Реализован OpenAI-совместимый серверный HTTP-адаптер. Он создаёт только текстовый черновик из заметки и названий работ; отдельные идентификаторы клиента, цены, сроки и гарантия не отправляются. Проверка результата: strict Zod object с problem, works и missing; пределы размера и времени, отказ от числовых финансовых условий и явная проверка мастером.

13 октября 2026 подключён OpenRouter с локальным ключом и моделью `liquid/lfm-2.5-2.6b:free`. Через адаптер проекта получено валидное объяснение вымышленной заметки о шумящем кулере и пыли. Для OpenRouter добавлена точная JSON-схема; серверная Zod-проверка сохранена. При подборе модели наблюдались 402, 429 и отклонённые ответы неверного формата. Успешное подключение не подтверждает стабильность и качество на широком наборе случаев. Проверен также тестовый локальный HTTP-сервер: корректный JSON, неверная структура, недоступность провайдера и ответ с денежными условиями. Интерфейс не показывает фиктивную генерацию. Ручной сценарий без ключа проверяется браузерным тестом.

Prompt injection снижено системной инструкцией о недоверенном вводе и узкими полномочиями. Гарантии отсутствия выдуманных фактов нет; поэтому перенос текста выполняется мастером после проверки. Ограниченное удаление телефонов/email не является гарантированной анонимизацией.

Документированный HTTP контракт: [OpenAI Chat API](https://developers.openai.com/api/reference/resources/chat). Совместимость с конкретным провайдером и моделью нужно подтвердить перед пилотом: поддержка response_format и max_tokens может отличаться.
