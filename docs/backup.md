# Резервная копия и проверка восстановления

Команды читают DATABASE_URL из локального `.env`. Нужны PostgreSQL client tools (`pg_dump`, `pg_restore`) в PATH либо установленная скриптом запуска Windows PostgreSQL в `.local/postgres/pgsql/bin`.

```powershell
npm run db:backup
npm run db:verify-restore
```

Первая команда создаёт custom-format архив и JSON с датой/SHA256 в `.local/backups`. Вторая дополнительно восстанавливает только что созданный архив в отдельную БД со случайным суффиксом `_restore_…`, сравнивает полные отпечатки данных всех public-таблиц с тем же исходным snapshot и удаляет созданную временную БД. Рабочая база не заменяется. Нужны права CREATE DATABASE. Автоматическая проверка разрешена только на localhost/127.0.0.1. `--keep` оставляет временную БД для отдельной ручной проверки:

```powershell
npm run db:verify-restore -- --keep
```

Не направляйте restore поверх рабочей базы. Для восстановления сохранённого архива создайте отдельную пустую БД на совместимом сервере и выполните `pg_restore --dbname <имя_новой_БД> --exit-on-error --no-owner --no-privileges <архив.dump>`, задавая PGHOST/PGPORT/PGUSER/PGPASSWORD через защищённое окружение. Сначала сверьте SHA256 с JSON, затем проверьте приложение с адресом восстановленной БД. Переключение рабочей системы требует отдельного плана и проверки сессий/данных; эта команда его автоматически не выполняет.

Архив содержит персональные данные, хеши паролей и сессии. Он исключён из Git; не прикладывайте его к тестовому заданию. Копия на том же диске не защищает от потери компьютера. Для эксплуатации нужны зашифрованное отдельное хранилище, расписание, срок хранения и регулярные проверки восстановления. Unix mode не гарантирует эквивалентную Windows ACL-защиту. Скрипт не делает шифрование и не запускается по расписанию.

Проверка отпечатков собирает содержимое таблиц в памяти PostgreSQL и рассчитана на небольшую пилотную базу. Проверены только локальная PostgreSQL 17 и данные этого MVP, не аварийное восстановление большого production-кластера. Приложение хранит данные в БД; отдельного хранилища загруженных файлов нет.

15 октября 2026 проверены 15 таблиц: `verified: true`, исходная база сохранена, временная удалена. Архив и полный локальный отчёт остаются в `.local/backups`.
