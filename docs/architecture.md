# Архитектура

## Стек и границы

Next.js 16 App Router, React, строгий TypeScript, Tailwind CSS 4, PostgreSQL 17, Prisma 7 с pg adapter, Better Auth, Zod, Vitest и Playwright. Клиентские компоненты читают данные из no-store API; служебные API всегда получают сессию на сервере. Статическая оболочка не содержит персональных данных. Нет клиентского массива вместо базы и нет localStorage для сохранения смет.

Официальные документы, проверенные при разработке: [Next.js](https://nextjs.org/docs/app/getting-started/installation), [Prisma 7](https://www.prisma.io/docs/orm/v7/prisma-client/setup-and-configuration/introduction), [Better Auth + Prisma](https://better-auth.com/docs/adapters/prisma), [Tailwind](https://tailwindcss.com/docs/installation/framework-guides/nextjs), [Vitest](https://vitest.dev/guide/), [Playwright](https://playwright.dev/docs/intro).

## Данные

User, Account, Session, Verification принадлежат Better Auth. Workshop связан с одним User через уникальный ownerId. Workshop создаётся PostgreSQL-триггером в одной транзакции с INSERT пользователя, название берётся из проверенного регистрационного поля. GET служебных API читает мастерскую и не создаёт данные.

Estimate принадлежит Workshop, содержит номер и currentVersionId. Version содержит снимок клиентского имени, устройства, внутренней заметки, объяснения, срока, гарантии, даты действия и целого итога. Item относится к конкретной Version. Question хранит исходный вопрос, ответ мастера и времена; Decision уникален по versionId и хранит approved/declined. Event хранит автоматически созданное событие без заметок и токенов. PublicLink содержит только SHA-256 хеш криптографически случайного 32-байтового токена, времена выпуска и отзыва.

UTC обеспечивается параметром соединения pg `timezone=UTC`, включая database defaults. На экране используется Asia/Tashkent. Денежные значения — целые числа в сумах: количество 1–100, цена 0–100 млн, 1–30 позиций, итог до 1 млрд. Итог сервер всегда вычисляет из позиций; пользовательский total игнорируется. Zod и CHECK constraints отклоняют недопустимые значения.

## Состояния

Решение, дата действия, replacedAt и доступность PublicLink независимы. Показанный статус вычисляется: черновик → факт замены → ранее принятое решение → отзыв ссылки → истечение → неотвеченный вопрос → ожидание. Поэтому решение остаётся видно после истечения/отзыва, а у заменённой версии оно дополнительно сохраняется в карточке истории. Статус «ссылка отозвана» добавлен для явного объяснения доступности.

## Транзакции и гонки

Все изменения существующей сметы сначала выполняют `SELECT ... FOR UPDATE` на одной строке Estimate, затем внутри той же транзакции повторно читают актуальные условия. Это общий порядок блокировки для сохранения, клонирования, публикации, ответа, решения и управления ссылкой. Проверка владельца находится внутри заблокированного пути. Публичный запрос сначала определяет смету по хешу, но после блокировки заново читает ссылку, текущую версию, решение и вопросы.

Публикация блокирует смету, проверяет черновик и будущий срок, заменяет предыдущую версию, публикует новую, переключает currentVersionId и выпускает токен в одной транзакции. Клиент, завершивший решение первым, получает сохранённое решение старой версии; если первой завершена публикация, старое решение отклоняется. UNIQUE Decision.versionId дополнительно исключает дубликаты. Частичные уникальные индексы исключают параллельные черновики, несколько активных ссылок и несколько неотвеченных вопросов. Composite FK исключает ссылку Estimate на Version чужой сметы. Триггеры защищают опубликованные условия и позиции от UPDATE даже вне прикладного сервиса.

Зависимые записи удаляются каскадно только при удалении владельца (в тестах — созданных текущим прогоном). В интерфейсе удаления смет нет. После публикации редактирование создаёт новый черновик, предыдущая ссылка продолжает действовать до его публикации.

## Вход, права и ссылки

Better Auth хранит хеши паролей и серверные сессии. Cookie httpOnly, SameSite=Lax; Secure включается при HTTPS BETTER_AUTH_URL. Собственные POST API требуют точное совпадение Origin с настроенным адресом; Better Auth дополнительно проверяет trustedOrigins. Все чтения служебных данных фильтруются workshopId. Чужие/отсутствующие сметы дают одинаковую ошибку. Публичные страницы выдают явный allowlist полей и не раскрывают внутреннюю заметку, аккаунт, события и хеши ссылок.

При выпуске токен возвращается только авторизованному владельцу. При перезагрузке восстановление невозможно, поэтому есть перевыпуск и отзыв старого токена. Ссылки не включаются в события и логи. Dev incoming-request logging Next.js отключён. Proxy access/error logs при внешнем размещении тоже должны исключать URL `/c/*` и `/api/service/public/*`. Cookie и ключи нельзя журналировать. noindex/nofollow, Referrer-Policy no-referrer, X-Frame-Options DENY, nosniff и private no-store применяются ко всем страницам/API. Пользовательский текст отображается React как текст, без dangerouslySetInnerHTML.

Временные окна rate limiting хранятся в PostgreSQL, увеличиваются атомарным UPSERT: глобальный лимит auth, email, мастерская для AI, хеш ссылки для публичных действий. Это работает через общую базу для нескольких процессов. Дополнительный внутренний лимит Better Auth — в памяти процесса. Не доверяем произвольному X-Forwarded-For. Для серьёзной публичной нагрузки нужны edge/proxy limits; текущая схема может быть использована для временного отказа обслуживания конкретному email/ссылке. Старые Throttle-записи удаляются обслуживанием базы, не влияет на бизнес-историю.

## AI

Подбор по каталогу получает до 100 собственных ServiceTemplate по workshopId, передаёт модели только технические ID и названия и проверяет ID/цитаты в ответе. Цена/количество подставляются сервером. Перед переносом клиент повторно проверяет актуальный каталог и изменения формы. Модель не сохраняет данные. Внешняя платная модель блокируется до HTTP-запроса без явно включённого AI_ALLOW_PAID_MODELS; настройку включают только после согласования расходов. Локальные endpoints и OpenRouter `:free` допускаются без него.

`src/lib/ai.ts` использует документированный OpenAI-совместимый HTTP API. Server-only конфигурация, JSON response, Zod strict schema, timeout 15 секунд, до 24 KB ответа. Вход — до 4000 символов заметки и 30 названий работ. Клиентский API body ограничен 32 KB потоковым чтением. Нет бесконечных повторов. Отдельные клиентские идентификаторы и финансовые/договорные поля не передаются; заметка проходит ограниченную редакцию очевидных идентификаторов. Числовые условия в объяснении отклоняются. Master review обязателен: prompt и схема не гарантируют правильность. AI не может менять цены, публиковать смету или принимать решение.

## Эксплуатация

ServiceTemplate хранит свои работы/цены мастерской; в смету копируются значения, а не динамическая ссылка на прайс. Незавершённый ввод временно хранится в sessionStorage той же вкладки по ключу мастерской/сметы/версии, срок проверяется при чтении (24 часа), после сохранения и выхода копия удаляется. Это не замена записи в PostgreSQL. Печатная версия не содержит внутреннюю заметку; колонтитулы браузера с URL нужно отключать при экспорте.

Проверенное локальное резервное восстановление: согласованный pg_dump snapshot, отдельная временная база, pg_restore и сравнение отпечатков всех 15 таблиц. Внешнее хранение, расписание и production-мониторинг не настроены. [Инструкция](backup.md).

Docker volume сохраняет PostgreSQL. На текущей машине проверяется отдельный локальный кластер в `.local`, игнорируемый Git. Тестовый wrapper допускает только отдельную локальную базу `_test`, передаёт runtime конфигурацию процессу проверки и выполняет только миграции без reset. E2E использует production build, порт 3078 и тестовую базу. Сборка приложения — независимая от AI-ключа. Политики резервных копий, мониторинг и аудит хостинга требуют отдельной подготовки перед пилотом.
